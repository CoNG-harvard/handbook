# TurtleBot3 documentation review — 2026-09-28

## Scope and evidence

Added TurtleBot3 Burger as the fourth project, using the user-supplied Google document **Getting started with Turtlebots**, accessed through the signed-in browser. The supplied Documentation folder was inspected to identify the relevant source; unrelated lab documents were not incorporated. This record deliberately omits source credentials, private addresses, and research launch commands.

The source identifies Burger robots, Ubuntu 20.04 with ROS 2 Foxy, shared-network access, robot-specific names, and optional OptiTrack tracking. Its Humble links conflict with its Foxy description. The new guide uses version-matched instructions and does not infer the currently installed versions from the age of the source.

The source's custom device bringup and research-control packages are excluded. Standard ROBOTIS launch behavior is not represented as reproducing lab namespaces. The optional tracking section explains the existing ROS 1 client/bridge arrangement without claiming that VRPN requires ROS 1 or publishing undefined local aliases.

## Public references checked

- [ROBOTIS features and components](https://emanual.robotis.com/docs/en/platform/turtlebot3/features/): Burger components, lack of a standard camera, kit revision differences. Quantities are per robot, not observed fleet inventory.
- [ROBOTIS assembly](https://emanual.robotis.com/docs/en/platform/turtlebot3/hardware_setup/): model-specific assembly route.
- [ROBOTIS PC setup](https://emanual.robotis.com/docs/en/platform/turtlebot3/quick-start/), [bringup](https://emanual.robotis.com/docs/en/platform/turtlebot3/bringup/), and [basic operation](https://emanual.robotis.com/docs/en/platform/turtlebot3/basic_operation/): installation, network discovery, and operator-led first checks. Users must select the matching ROS release.
- [Official Foxy installation source](https://raw.githubusercontent.com/ros2/ros2_documentation/foxy/source/Installation/Ubuntu-Install-Debians.rst): Ubuntu Focal support and shell setup. The rendered docs site presented automated-access protection; the official source was readable. Do not treat this as a dead link.
- [Official REP-2000 source](https://raw.githubusercontent.com/ros-infrastructure/rep/master/rep-2000.rst): Foxy targeted Ubuntu 20.04; support ended May 2023. The handbook links to the human-readable REP page, whose automated rendering was also blocked.
- [OptiTrack rigid bodies](https://docs.optitrack.com/motive/rigid-body-tracking) and [streaming](https://docs.optitrack.com/motive/data-streaming): tracked marker arrangements and VRPN rigid-body streaming.

The public ROBOTIS e-Manual remains readable but advertises migration to ROBOTIS Docs. Links should be revisited if those legacy pages redirect or disappear.

## Editorial choices

- Preserve the existing shared RTX workstation for VLA Pipeline, Self Improvement Learning, and ABC Box. Do not claim Foxy is compatible with its Ubuntu 24.04 installation or that an additional physical computer must be purchased.
- Provide four pages: overview, equipment/connections, basic software, and readiness. Add the project to the full sidebar, project directory, and shared references.
- Use a photograph placeholder. The source document contained no station image; no synthetic hardware visual was added.
- Keep optional room tracking separate from basic robot readiness. Do not invent an OptiTrack camera count or treat the table as a complete room procurement plan.
- List unresolved hardware revisions, fleet size, current versions, operator environment, photo, and optional tracking configuration centrally.
